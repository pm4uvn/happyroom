# HAPPYROOM — MVP Gap Analysis

Audit date: 2026-11-05. Status values: **Implemented** (works end-to-end and is covered by a test that was run), **Partial**, **Missing**, **Blocked** (needs something outside the repository).

## 1. Audit at the start of this iteration

What existed (inspected, not assumed):

| Area                 | Finding                                                                                                                                            |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apps/web`           | Landing page, 3D preview (local only, labelled as such), i18n en/vi/ja, `/api/health`, `/api/events`. No `/create`, `/join` or `/r/[slug]` routes. |
| `apps/game-server`   | README only. No Colyseus code, no package.json.                                                                                                    |
| `packages/shared`    | Zod schemas incl. `createRoomInputSchema`, protocol v1 message schemas, catalogs, room layout.                                                     |
| `packages/game-core` | Ceremony FSM, permissions, movement validation, token bucket — unit-tested, not wired to anything.                                                 |
| Database             | 22 tables incl. rooms, guest_sessions, invitations, participants, wishes, room_gifts, ceremonies; RLS; integration-tested.                         |
| Env                  | No join-grant key; `NEXT_PUBLIC_FEATURE_*` flags `false`.                                                                                          |

Baseline verification (before changes): lint ✅, typecheck ✅, 87 unit tests ✅, 16 DB integration tests ✅, 28 E2E ✅.

**The actual blocker for Create/Join:** there was no back end for it. No guest-session service, no room/invitation API, no access check, no join-grant signing and no game server existed, so the CTAs were (correctly) disabled. The database schema and pure game logic were ready but unused.

## 3. Known blockers

1. **GLB asset**: `HappyRoom_BirthdayStudio_V2.glb` must be added at `apps/web/public/assets/rooms/`. Until then the procedural room is used.
2. **Supabase project schema**: `.env` contains the project URL and publishable/anon keys, but the remote database has no tables yet (`PGRST205`). Applying migrations needs the database connection string (secret) — see README.
3. **Object storage** credentials for photo uploads.
4. **Load-test infrastructure** to validate the 20-participant target.
